# MotoristaOPS — Design Capability Matrix

**Status: CANÔNICO — mapa de capacidades do Orchestrator**

O orquestrador deve selecionar capacidades por problema, não por ferramenta.

## 1. Estratégia e briefing
- transformar demanda vaga em briefing acionável;
- definir objetivo, público, contexto e critério de sucesso;
- decompor problemas;
- priorizar risco × impacto × esforço;
- identificar lacunas de informação antes de produzir.

## 2. Branding
- aplicar Brand Book V2;
- auditar coerência;
- detectar desvio;
- resolver aplicação nova sem criar identidade paralela;
- classificar presença de marca L1/L2/L3;
- garantir assinatura correta.

## 12. Regra de uso

Uma tarefa pode ativar múltiplas capacidades, mas deve existir:

**um objetivo → um responsável lógico → critérios de aceite explícitos.**

O orquestrador integra as capacidades e impede que uma disciplina local comprometa o sistema global.
