# Project Bootstrap

## Objetivo

Usar MotoristaOPS como projeto-laboratório e infraestrutura de referência para futuros projetos sem copiar sua identidade.

## O que é portátil

- Kernel de orquestração.
- Request Resolver.
- Decision Memory.
- Curation System.
- Prompting Protocol.
- Reference Intake.
- Capability Matrix.
- Execution Protocol.
- Quality Gates.
- Failure Memory.
- arquitetura de estados CANONICAL/EXPERIMENTAL/DEPRECATED/BLOCKED.
- separação generativo × determinístico.
- modularidade.
- loop de aprendizado.
- disciplina de evidência.

## O que não é portátil

- nome MotoristaOPS;
- tese específica;
- paleta;
- tipografia;
- brasão/logo;
- assets;
- fotografia;
- regras específicas do serviço;
- CTA/canais específicos;
- pricing;
- veículo;
- persona de Henrico;
- composição visual específica.

## Processo para novo projeto

1. copiar o kernel universal;
2. criar `PROJECT_PROFILE.md`;
3. definir autoridade e fontes;
4. criar Brand/Design resolver específico;
5. registrar assets;
6. criar tokens;
7. criar failure memory vazia;
8. criar curadoria raw/knowledge;
9. definir gates por superfície;
10. executar primeiro projeto como stress test.

## Regra

Novo projeto herda **infraestrutura**, nunca herda identidade por acidente.
