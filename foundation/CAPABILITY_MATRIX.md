# Foundation Capability Matrix

O orquestrador precisa ter visão transversal suficiente para identificar o problema, escolher a especialidade correta, impor o contrato e validar a saída.

- autoridade e precedência;
- modularidade;
- contratos;
- versionamento;
- estados CANONICAL/EXPERIMENTAL/DEPRECATED/BLOCKED;
- risco e reversibilidade;
- changelog;
- release.

## 12. Regra de roteamento

O orquestrador não precisa substituir o especialista. Precisa:

1. reconhecer a disciplina;
2. saber quais fontes governam;
3. definir o contrato de entrada;
4. escolher a ferramenta/capacidade;
5. saber o que verificar;
6. rejeitar uma saída tecnicamente boa que viole o sistema.
