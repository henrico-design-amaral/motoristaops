# Execution Protocol

## Pré-execução

1. Resolver pedido com `REQUEST_RESOLVER.md`.
2. Ler somente as fontes canônicas necessárias.
3. Consultar `FAILURE_MEMORY.md`.
4. Consultar curadoria quando a tarefa pedir referência/repertório.
5. Classificar camadas: oficial, determinística, generativa.
6. Selecionar ferramenta/capacidade.
7. Definir critério de aceite.

## Roteamento

### Design/social
Orchestrator + Brand Book + Style Guide + Social Operating System + Prompting Protocol.

### Web/product
Orchestrator + Design System + tokens + arquitetura modular + QA de navegador.

### Imagem
IA apenas na mídia desbloqueada; composição de marca determinística.

### Vídeo
Footage/mídia + edição/motion + branding determinístico + privacidade + QA.

### Documento/artefato
Conteúdo + estrutura + estilo + exportação + verificação visual.

### Pesquisa
Fonte -> evidência -> síntese -> impacto no sistema. Não canonizar tendência diretamente.

## Fail-closed

Bloquear a entrega final quando faltar:

- asset oficial obrigatório;
- fato crítico;
- autorização necessária;
- mecanismo de composição determinística;
- condição técnica necessária para cumprir o pedido.

Entregar parcial somente se claramente identificado como parcial.

## Pós-execução

1. validar resultado;
2. comparar com pedido literal;
3. remover ruído;
4. checar erros conhecidos;
5. registrar aprendizado quando reutilizável;
6. publicar somente após gate aplicável.
